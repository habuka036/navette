# ADR-0004: タスク状態の永続化（SQLite + Markdown）と人間の承認ゲート

- Status: Accepted
- Date: 2026-10-14

## Context

NAVETTE は開発タスクの状態と実行履歴を管理する。プロセス再起動をまたいでタスクの
進捗・履歴を失わないため永続化が必要である。また、重要な操作を Agent に無断で
実行させないため、人間の承認を挟む仕組みが要る。

初期 PoC では高度なデータストアは不要で、SQLite と Markdown による永続化で十分と
判断されている。

## Decision

- タスクの状態と実行履歴を永続化する。初期 PoC では SQLite（構造化された状態・履歴）と
  Markdown（人間が読む実行ログ・成果物）を用いる。
- 重要な操作（例: 破壊的コマンド、外部副作用、クラウド API 呼び出し）には人間の承認を
  必要とする。初期 PoC の承認ゲートは CLI 対話（標準入力による確認）で実現する。

スキーマ・状態機械・承認対象の具体は NAVETTE の Feature Spec（design）で確定する。

### 承認時の具体化事項（2026-10-14）

- 未承認タスク（承認待ち状態）は永続化され、CLI 切断やプロセス再起動後も未承認状態を
  維持する。再起動時に未承認状態が「承認済み」や「失敗」へ暗黙に遷移してはならない。
- NAVETTE は Une Feuille が利用できなくても、基本的なタスク実行と永続化（SQLite +
  Markdown）が可能である。Une Feuille 連携は任意機能として分離する。

## Rationale

- SQLite は MILLEFEUILLE と同じく pure-Go で CGO 不要、単一ファイルで PoC に適する。
- Markdown は人間が履歴・成果物を直接読め、レビューと承認判断を支援する。
- CLI 対話の承認は PoC で最も単純かつ確実。ファイルベース承認は将来 UI を分離する際に
  再検討する。
- 代替案 (A) 外部 DB / メッセージキュー：PoC では過剰で運用コストが高いため不採用。

## Consequences

- 利点：再起動をまたいだ状態・履歴の保持と、人間による制御点を最小構成で実現できる。
- 制約：CLI 対話の承認は対話端末前提。非対話実行（CI 等）では別の承認方式が必要になる。
- 将来の影響：承認方式（ファイルベース / Web UI）やデータストアの差し替えは後続 ADR で
  扱う。Une Feuille が未完成でも NAVETTE の永続化は本 ADR の SQLite / Markdown で自立して
  動作する。
